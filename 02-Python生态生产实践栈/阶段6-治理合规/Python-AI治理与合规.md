# 阶段6 · Python AI 治理与合规风控

> 对齐理论层 [`1.7-治理与安全原则`](../../01-通用理论原理层/1.7-治理与安全原则.md) + 横向支撑「安全合规治理」；Java 栈对照 `../../03-Java生态生产实践栈/阶段6-治理合规`。
> 素材：ai-agent-book 安全相关实验、hello-agents 安全实践、javaguide `llm-security` 方法论（理论 1.7 已沉淀）。

## 1. 安全风险与防护（理论 1.7 落地）

| 风险 | Python 防护 |
|------|------------|
| **Prompt 注入** | 输入过规则 + LLM 判别隔离；系统指令与用户内容严格分离；用结构化分隔符 |
| **越权/工具滥用** | 工具调用前做权限校验；写操作需确认；MCP Schema 校验入参 |
| **数据泄露** | 多租户记忆按 `user_id` 分区 + 检索租户过滤；输出前脱敏（PII 正则/模型审核） |
| **内容违规** | 输出内容审核（敏感词 + 模型判别）后返回 |
| **供应链** | 锁定依赖（`uv lock`）、镜像扫描、MCP Server 来源可信 |

## 2. 数据防护实现

- **向量数据脱敏**：入库前对 PII 字段脱敏/掩码；检索后按权限还原。
- **用户数据隔离**：`where tenant_id = ?` 强制过滤；记忆读写携带租户上下文。
- **敏感信息处理**：日志脱敏中间件（过滤密钥/手机号/身份证）；env 密钥用 Secret 管理。

## 3. 合规审计

- **操作审计**：记录每次工具调用、决策链路、人工确认，存审计表/日志，可追溯。
- **合规报表**：定期导出调用量、违规拦截、数据访问报表，对接企业合规体系。
- **可解释性**：LangFuse Trace 提供"为什么这样回答"的依据（检索来源、工具路径）。

## 4. Agent 权限治理（MCP/工具）

- **最小权限**：工具仅暴露必要能力；危险工具（删除/外发）默认禁用，显式开启 + 审批。
- **沙箱隔离**：代码执行（Coding Agent）在受限容器/沙箱，限制网络与文件系统。
- **调用审批流**：关键动作（发邮件/改数据库）需人工 or 工作流审批。

## 5. 与 Java 栈对照

| 维度 | Python | Java |
|------|--------|------|
| 鉴权 | FastAPI 依赖注入 + JWT/API Key | Spring Security + Sa-Token |
| 数据加密 | 应用层脱敏 + 字段加密 | 数据库加密 + 脱敏 |
| 审计 | 日志/审计中间件 | 操作日志 + 审计链路 |
| 沙箱 | 容器/受限执行 | 同上 + 企业安全体系对接 |

> 治理原则与风险清单双栈一致（理论 1.7 归一化），实现因语言生态差异。

## 6. 双栈治理归一化结论

无论 Python 还是 Java，Agent 治理的**本质相同**：身份鉴权、输入隔离、工具最小权限、输出审核、数据隔离、可审计。差异仅在于框架（FastAPI 依赖 vs Spring Security）与生态组件，原理可直接迁移。
