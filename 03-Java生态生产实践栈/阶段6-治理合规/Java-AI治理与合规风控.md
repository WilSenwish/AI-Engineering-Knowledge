# 阶段6 · Java AI 治理与合规风控

> 分级：🟡 生产最佳实践 ｜ 来源：`素材收集/03-nageoffer-ragent.md`、`素材收集/04-javaup-nexus-agent.md`、`素材收集/05-javaguide-ai.md`（安全实战/大模型网关）
> 定位：规划"阶段6 治理合规·Java 生态"。Java 业务侧治理强项在**权限/审计/数据隔离/事务一致性**——把 AI 能力纳入既有企业安全体系。对齐理论层 `1.7-治理与安全原则` 与 `04-横向支撑域/安全合规治理.md`。

## 一、认证与权限（复用企业体系）

- **认证**：Sa-Token / Spring Security OAuth2，与现有 SSO 打通；用户身份贯穿 AI 调用全链路。
- **数据归属校验**：问答/文档/记忆按 `userId`/`tenantId` 隔离，越权访问在入口拦截（Ragent `system` 模块职责）。
- **最小权限**：AI 服务仅持必需权限；调用下游系统走服务账号 + 作用域限制。

## 二、Prompt 注入与越权防护

- **输入净化**：用户问题经改写/校验，剥离可疑指令注入；工具调用的写操作**人工确认**（Ragent：MCP 写操作确认规则）。
- **工具白名单**：MCP 工具按场景声明可用集合（如意图树节点指定工具），非全量暴露。
- **Schema 校验**：MCP 工具入参强校验，拒绝畸形参数；模型方言适配器测试覆盖异常分支。
- **无证据短路**（Nexus）：检索无证据时直接告知用户，架构层杜绝编造，降低幻觉型合规风险。

## 三、内容合规与审计

- **内容审核**：生成结果经敏感词/合规规则过滤；高风险场景接第三方审核 API。
- **全链路审计**：AOP 横切记录链路追踪/幂等/审计日志（Ragent 设计模式清单）；谁、何时、问了什么、调了什么工具、得到什么答案，可追溯。
- **配置一致性**：启动期校验关键配置（模型档位、向量库、限流参数），防误配导致的安全或成本事故。

## 四、数据安全与多租户

- **隔离**：向量库/ES/Redis/记忆按租户分区；PGVector 用 `tenant_id` 过滤，ES 用索引隔离。
- **传输与存储**：敏感数据加密（落库加密、传输 TLS）；记忆持久化脱敏。
- **可调出权**：用户可查询/删除自己的对话与记忆（合规"被遗忘权"）。

## 五、成本与限速治理（衔接 04-横向支撑域/成本ROI）

- **模型档位**：按问题复杂度路由不同成本模型（Ragent 档位 + 首包探测）。
- **流量保护**：Redis ZSET 公平排队 + Lua 原子抢占 + 过期信号量 + Pub/Sub 唤醒，防单用户突发压垮模型、保障公平配额。
- **网关层治理**：大模型网关统一限流/配额/成本统计（见 `05-javaguide-ai.md` 网关子页）。

## 六、与 Python 栈阶段6 对照

| 治理点 | Python 栈 | Java 栈 |
|--------|----------|--------|
| 认证授权 | 框架级中间件 | Sa-Token/Spring Security 复用企业 SSO |
| 审计 | 应用埋点 | AOP 横切 + 既有审计平台 |
