## 一、项目定位与主张

- **核心主张**："调 API ≠ 生产级 Agent"。工程能力（文档解析、分块、问题改写、混合检索、幻觉控制）是 AI 工程师真正的护城河，不随模型迭代过时。
- **覆盖技术**：Agent 智能体、SubAgent、ReactAgent、AgentScope 多智能体、联网搜索、RAG、MCP 工具、Skills、会话记忆、生命周期治理、Harness 治理。

---

## 二、系统架构总览（六大模块协同）

1. **用户入口**：对话界面，不直接把问题扔给模型。
2. **前置编排中心**：会话记忆、问题改写、子问题拆分、歧义澄清等确定性编排。
3. **三层执行器**：按场景分流（歧义追问 / 知识问答 / 开放式 Agent）。
4. **知识底座**：文档解析、切块、向量化、双引擎索引、文档结构图谱。
5. **混合检索**：向量 + 关键词并行、RRF 融合、可选 Rerank、Parent-Child 聚合。
6. **工程化护栏**：流量保护、并发控制、全链路观测、安全沙箱。

> 一句话链路：用户提问 → 编排决策 → 执行器分流 → 知识检索 → 证据驱动生成。

## 三、核心能力清单

| 能力 | 关键设计 |
|------|----------|
| ReAct Agent 完整实现 | 联网搜索/工具调用/多步推理/Checkpoint 持久化/并行工具/调用次数限制 |
| 三层执行器体系 | 确定性编排后按场景分流；歧义追问→知识问答→开放式 Agent 优先级链（核心竞争力） |
| RAG 前置编排引擎 | 路由判定/问题改写/子问题拆分/知识域收缩/歧义检测，模型回答前做完所有决策 |
| 双通道混合检索 | 向量 + 关键词并行 + RRF 融合 + 可选 Rerank + Parent-Child 块聚合 |
| 证据预算控制与无证据短路 | 字符级预算裁剪；无证据直接告知，架构层杜绝幻觉 |
| 三种会话记忆策略 | 无记忆 / 滑动窗口 / 摘要压缩，可切换对比 |
| MCP 工具协议 | 基于标准协议动态发现外部工具，即插即用（非硬编码 Function Call） |
| Skills 能力扩展 | `SKILL.md` 声明式定义，目录化管理、自动加载、引用脚本/参考资料 |
| Neo4j 文档结构图谱 | Document→Section→Item 层级图，章节导航、邻接遍历、子节点展开 |
| 知识路由三级漏斗 | Scope→Topic→Document 语义+词法+实体混合打分，置信度不够降级，不硬猜 |
| 影子路由质量观测 | 用户手动选文档时后台静默跑完整路由，对比命中率/置信度/候选排名，持续优化 |
| 文档处理异步流水线 | Tika 多格式解析、四种切块策略组合、PGVector + Elasticsearch 双引擎、分步任务日志 |
| 组合式切块引擎 | 结构切块(主干)+递归(兜底)+语义(边界)+LLM智能(疑难)，按类型自动推荐 |
| 联网搜索与工具调用 | Tavily 集成、重试/指数退避/异常兜底、Hook 限制调用次数防死循环 |
| 推荐追问生成 | 主回答后额外调模型生成最多 3 个追问 |
| SSE 流式输出 | 正文分片实时推送，结束补来源+追问，支持主动停止 |

## 五、与 Ragent（nageoffer）的对照（知识库双 Java 范例）

| 维度 | Ragent (nageoffer) | Nexus Agent (javaup) |
|------|--------------------|----------------------|
| 执行范式 | v1 Workflow + v2 ReAct 并存 | 三层执行器（歧义/知识/开放式 Agent） |
| 检索 | 向量/关键词/图谱/联网 + RRF + Rerank | 向量/关键词 + RRF + Parent-Child 聚合 |
| 记忆 | 最近 N 轮 + 持久化摘要；Agent 三层上下文 | 三种策略可切换（无/滑动窗口/摘要压缩） |
| 图谱 | 知识图谱参与召回 | Neo4j 文档结构图谱（Document→Section→Item） |
| 路由 | 树形意图识别、多库路由 | 三级漏斗 + 影子路由质量观测 |
| 工具 | AgentScope MCP + 写操作人工确认 | MCP 标准 + Skills 声明式 + Hook 限制 |
| 可观测 | LangFuse Trace | 全链路观测 + 影子路由 |
| 技术栈 | Spring Boot 4 + React 18 | Java 栈（ReAct/SubAgent/AgentScope） |

> 两者共同印证：企业级 Java AI 应用 = 分层架构 + 检索工程 + 上下文/记忆治理 + 模型容错 + 全链路追踪 + 安全护栏，而非"套框架"。
