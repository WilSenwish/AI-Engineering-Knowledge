# 1.3 RAG 技术体系

> 分级：⚪ 理论原理 + 🟡 生产最佳实践 ｜ 来源：`素材收集/01-xiaolinnote-ai-大模型面试题.md`（RAG23题）、`素材收集/05-javaguide-ai.md`（《RAG 基础概念》深解）

## 一、为什么需要 RAG（补 LLM 三短板）

1. **知识时效性**：训练截止后的新事件/政策/文档，靠动态检索注入。
2. **私有数据访问**：只提相关片段给 LLM，不暴露全量企业数据。
3. **幻觉控制**：提供明确参考文本降低编造概率（非彻底消除，需配引用校验/拒答/反馈闭环）。

> 传统搜索 vs RAG：用户目标"找到材料"→搜索框更直接、低成本、可审计；"读完给结论"→RAG。企业常**两套入口并存**。

## 二、工作原理（两阶段）

- **离线索引**：输入 → 清理 → 增强元数据 → **Chunking**（兼顾语义完整 / Embedding 长度 / 上下文窗口 / 召回粒度）→ **Embedding** → 存入向量库（Milvus / pgvector / ES / Faiss）。
- **在线检索**：请求 →（Query 改写）→ 查询向量化 → 相似性检索 → 上下文增强(R) → LLM 生成(G) →（反馈）。

## 三、关键组件与优化方向

| 环节 | 关键点 | 常见坑 |
|------|--------|--------|
| 切分 Chunking | 语义完整、不切断、粒度适配检索 | 切太粗→召回噪声；切太细→语义断开 |
| Embedding | 维度 768/1024/1536/3072（非越高越好）；闭源(OpenAI/Cohere/Jina) vs 开源(BGE/GTE/E5) 按出网/私有化选 | MTEB 仅参考，需业务集评测 |
| 相似度 | 余弦（RAG 最常用，对长度不敏感）/ 内积（L2 归一化后≈余弦）/ 欧氏（对幅度敏感） | — |
| 向量库 | Milvus（大规模）/ pgvector（已有 PG）/ ES（全文+向量）/ Faiss（轻量） | 权限隔离、增量更新 |
| 检索优化 | Query 改写 / HyDE → 混合检索（向量+关键词）→ Rerank → 上下文压缩 | 答非所问多在**召回阶段** |

> **答非所问排查顺序**（javaguide 经验）：Chunk 切粗 → Query 未改写 → 关键词与向量未结合 → 重排缺失，逐项排查比换贵模型有用。

## 四、RAG vs 微调

| 维度 | RAG | 微调 |
|------|-----|------|
| 解决 | "不知新知识/私有知识" | "不会按你的方式说/做" |
| 知识更新 | 成本低（更新知识库） | 高（重新训练） |
| 可追溯 | 强（引用片段） | 弱 |

- **结合策略**：微调懂领域术语/格式，RAG 供实时可追溯证据；资源有限先稳 RAG 再考虑微调。

## 五、长上下文能否取代 RAG → **不能**

- 长上下文贵、慢、易噪声；百万级文档塞不下、成本延迟扛不住。
- **Lost in the Middle**（中间信息被忽略）。
- 权限隔离仍需应用层；可追溯性 RAG 更优。

## 六、RAG 演进三阶段

1. **Naive RAG**：切块 → Embedding → TopK → 生成（Demo 级）。
2. **Advanced RAG**：Query Rewrite / HyDE → 混合检索 → Rerank → 上下文压缩。
3. **Modular RAG**：检索器/重排器/压缩器/路由器/生成器可插拔，适合生产 / Agent。

## 七、高级 RAG 与图谱增强（补采深化）

### 7.1 切分与重排的工程经验
- **切分**：固定大小 → 语义切分，建议递归字符切分起步；避免一句话被切断、段落被拆开。
- **Re-rank（精排）**：Cross-Encoder 对初排结果精排，准确率提升 30-50%。**先检索 50-100 候选，重排到 Top-5/10** 性价比最高；简单事实查询可设阈值（初排 Top-1 低于阈值才触发重排）。
- **多路召回**：向量 + BM25 关键词混合，效果比单路好 10-30%；多通道并行，单通道失败不影响主链。

### 7.2 GraphRAG 与 LightRAG（图库增强）
> 来源：`素材收集/02-xiaolinnote-agent-图解Agent.md` ④

- **传统 RAG 痛点**：只能检索相似文本块，跨文档多跳推理失效、全局归纳（"本书主题"）无解、切块语义断裂。
- **GraphRAG（微软 2024.4）**：LLM 抽实体/关系建知识图谱；Local Search（图遍历邻居）+ Global Search（Leiden 社区检测 + 社区摘要 Map-Reduce）。代价：索引贵（"Token 焚烧炉"）、增量级联失效、延迟高（10s-1min）。
- **LightRAG（港大 2024.10）**：去社区层（省 80%+ LLM 调用）、**双层检索（低层实体 + 高层主题并行）**、追加式增量。Token 成本降 ~99%（百万 token 约 $0.15 vs GraphRAG $20-50），延迟 1-3s。
- **选型**：GraphRAG=重型武器（深度全局洞察、跨文档高价值推理、静态少更新、强可解释/审计）；LightRAG=轻巧刀具（频繁更新、成本敏感、C 端实时、10万-500万 token 甜蜜区）。务实路径：传统 RAG → 遇跨文档/全局问题升 LightRAG → 精度不足再上 GraphRAG。LightRAG 保留 Naive 模式兼容传统向量 RAG，是 GraphRAG 去社区层的轻量子集。

### 7.3 Embedding 演进
Word2Vec → BERT → BGE-M3 → **第四代 LLM-based（LLM2Vec / Qwen3-Embedding / Seed1.5-Embedding，2025 中英文 SOTA）**；选闭源/开源按出网/私有化需求，MTEB 仅参考需业务集评测。

### 7.4 效果量化（RAG 评估）
- **RAGAS**：用强 LLM 当裁判，自动算 Faithfulness / Answer Relevance / Context Recall 等指标（需 question/contexts/answer/ground_truth 数据集）。
- 其他：DeepEval（融入单元测试）、TruLens（深度可观测诊断）、ARES（LLM 生成合成评估数据）。
- 评估应纳入 CI 回归（对齐 `1.6 评估体系` Golden Set / 灰度）。
