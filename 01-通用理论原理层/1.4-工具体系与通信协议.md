# 1.4 工具体系与通信协议

> 分级：⚪ 理论原理 ｜ 来源：`素材收集/02-xiaolinnote-agent-图解Agent.md`（concept 分层）、`素材收集/05-javaguide-ai.md`（mcp/skills 子页地图）

## 一、底层能力分层（面试高频，极重要）

| 概念 | 角色 | 比喻 |
|------|------|------|
| **Function Call** | 基础调用能力（原子操作） | "打电话的能力" |
| **MCP** | 统一工具连接标准 | "公司通讯录/电话系统"（AI 界 USB-C） |
| **Skills** | 做事方法 / 知识层 | "岗位培训手册 / 菜谱" |
| **A2A** | Agent 间协作协议 | 横向通信（MCP 是竖向） |

- **Function Call**：一次性单步调用，是 Agent 的"原子操作"；一个任务可能触发十几次 FC，Agent 是 FC 的"高级编排"。
- **MCP**（Model Context Protocol）：Host(宿主) / Client(翻译官) / Server(暴露工具) 三角色；把 N×M 集成降为 **N+M**；工具可发现、运行时动态接入。
- **Skills**：`SKILL.md` 声明式定义（YAML 元数据 + 自然语言指令），教 Agent "怎么做"。关系：**MCP = 厨房（能做什么），Skills = 菜谱（该怎么做）**。
- **A2A**（Google 2025.4）：Agent Card(名片) / Task(任务生命周期) / Message&Artifact；基于 HTTP+JSON+SSE，支持异步长任务；与 MCP 互补（竖向接工具、横向 Agent 协作）。

## 二、工具分类（规划定义）

- **感知类**：读文件、查数据库、爬网页、调 API 获取信息。
- **执行类**：写文件、发消息、调用业务系统、执行代码。
- **协作类**：调用其他 Agent / 子 Agent（对应 A2A）。

## 三、生产接入要点（javaguide 视角）

- MCP / Function / Tool Calling 解决"怎么接工具"；生产难点在后面：**谁能调、能操作哪些数据、调用审计、失败回滚**。
- 工具安全沙箱：代码执行需沙箱（如 `execution_sandbox`），限制权限与资源。
- 网关层：统一鉴权、限流、审计、降级（见 `03-Java生态生产实践栈/阶段4` 大模型网关）。

## 四、MCP 深解（补采深化）

> 来源：`素材收集/05-javaguide-ai.md` ①

- **本质**：MCP = **MCP Client 与 Server 之间的通信协议**（Host 承载交互+模型调用，Client 连 Server，Server 暴露能力）；解决"同一工具交付多个 Host 时重复集成"，把 N×M 降为 N+M。
- **与 FC/Agent 链路关系**：FC 产生命令（结构化调用意图）→ MCP 传递命令并连接工具 → Agent 决定链路何时继续/结束。
- **能力类型**：Tools（执行动作）/ Resources（只读上下文，如文件/日志/Schema）/ Prompts（可复用提示模板）；Client→Server 进阶能力：Roots（目录范围，非沙箱需 Server 自做路径校验）、Sampling（Server 请求 LLM 生成）、Elicitation（向用户补充询问）。
- **传输**：JSON-RPC 2.0（偏方法调用，贴合工具调用）；stdio（本地子进程，stdout 不能打日志）+ Streamable HTTP（远程，可走网关鉴权限流）。
- **生产接入 checklist**：
  - Schema/版本：字段单位、时间格式、枚举写清；工具带版本号 + 灰度回滚；Schema 同时作运行时校验与模型提示。
  - 权限安全：目录/库/API 边界，读写分离，高危操作人工确认，返回脱敏，防路径遍历/SQL/命令注入；三方 Server 源码/依赖/权限审核。
  - 可观测：Trace ID + 结构化日志 + 完整调用链。成本归因：关联用户/业务线/工具。
- **Server 设计**：避免 `execute_sql`/`file_operation` 万能工具，按业务动作拆分（动词+名词 + description 写清适用/禁用场景）；大文件按 chunk（~100KB）读取；安全不靠模型，靠目录校验+沙箱+限流熔断。

## 五、Skills 深解（补采深化）

> 来源：`素材收集/05-javaguide-ai.md` ②

- **定义**：Skill = 写在 `SKILL.md` 中、可被发现按需读取的**任务说明**（规定"怎么做"，非工具能力）；解决跨会话规则复用 + 上下文腐化治理。
- **SKILL.md 结构**：YAML 元数据（name≤64 小写连字符；description 写清①做什么②何时用+触发词）+ 正文指令（默认方案/项目约束/IO 格式/失败处理，建议≤500 行，长内容拆 references/）。
- **与 MCP 区别**：Prompt(说什么) → FC(发动作) → MCP(接外部能力) → Skill(规定流程与约束)。协同：宿主把 Skill 简介放进上下文→模型路由命中→延迟加载完整 SKILL.md→按流程调工具。
- **三层渐进式披露**：广告层（仅元数据）→ 指令层（命中读正文）→ 资源层（按需读 references/scripts），精准加载缓解窗口退化。
- **企业价值**：团队经验资产化（评审/慢SQL/报表固化）；Checklist+验证节点防跳步；按任务风险分配自由度（迁移/部署低自由度+回滚，评审高自由度）。

> 关系回顾：**MCP = 厨房（能做什么），Skills = 菜谱（该怎么做）**；A2A 横向 Agent 协作。落地：Java 侧工具注册见 `03-Java生态生产实践栈/阶段2`；多 Agent 协作协议见 `1.5`。
