# 1.7 治理与安全原则

> 分级：⚪ 理论原理 + 🟡 生产最佳实践 ｜ 来源：`素材收集/05-javaguide-ai.md`（llm-security 子页）、`素材收集/01-xiaolinnote-ai-大模型面试题.md`（DB 越权/泄露）、规划"阶段6"

## 一、主要风险面

| 风险 | 表现 | 防护方向 |
|------|------|---------|
| Prompt 注入 | 恶意指令绕过系统提示、篡改行为 | 输入清洗、权限边界、输出校验 |
| 越权访问 | Agent 调工具访问无权限数据（如 DB 越权） | 工具级鉴权、最小权限、调用审计 |
| 数据泄露 | 敏感信息进上下文 / 输出 / 日志 | 脱敏、隔离、日志脱敏 |
| 内容违规 | 生成违规/敏感内容 | 输出审核、拒答策略 |

## 二、防护原理（分层）

1. **输入层**：Prompt 注入检测、用户输入隔离、工具调用白名单。
2. **执行层**：工具权限校验（谁能调、能操作哪些数据）、调用审计、失败回滚。
3. **输出层**：内容审核、引用校验、敏感信息过滤。
4. **数据层**：向量数据脱敏、用户数据隔离、数据库加密。

## 三、合规与伦理

- **数据合规**：个人信息保护、数据出境、训练数据版权。
- **内容合规**：生成内容审核、敏感信息过滤、违规拦截。
- **可解释与问责**：AI 决策可解释、责任边界、算法公平性。
- **审计**：操作日志、审计链路、合规报表（Java 侧见 `03-Java生态生产实践栈/阶段6`）。

## 四、工程落地要点

- 安全是"执行侧"问题：靠 Harness 约束层（硬编码边界 + 每步硬校验）+ 网关统一鉴权（见 `03-Java生态生产实践栈/阶段4` 大模型网关）。
- 把安全校验沉到环境（AGENTS.md / Hook / 测试），形成复利（见 1.2 Harness）。

## 五、安全风险与防护深解（补采深化）

> 来源：`素材收集/05-javaguide-ai.md` ④⑤

### 5.1 主要风险面
- **Prompt Injection**：直接（用户输入）/ 间接（网页/邮件/RAG/工具结果夹带指令）/ Jailbreak（对抗安全策略）。
- **工具越权与过度代理**：万能工具（`execute_sql`/`request_url`）致越权查询、退款、删数据；工具结果夹带"继续调用退款"；模型改 `tenantId`。
- **敏感数据泄露/跨租户**：PII/令牌经上下文、RAG、Memory、Trace、缓存或外发泄露；RAG 先取 Top-K 后过滤致越权文档入上下文；Trace/缓存跨租户复用；HTTP 工具访问云元数据（SSRF）。
- **供应链**：恶意 MCP Server / Skill / 三方依赖、知识库投毒；Token Passthrough（原样透传令牌）。
- **代码执行与隔离失效**：Shell/Python 执行致文件泄露、SSRF、横向移动；模型生成 HTML/SQL/Shell 直插页面/库致 XSS/注入。
- **多 Agent 级联**：目标劫持、工具滥用、级联故障、责任难定位。

### 5.2 Java/Spring 后端落地防护
- **鉴权与身份分离**：`ExecutionContext(tenantId,userId,authorities)` 来自登录态、不进模型可改参数；执行前服务端用 `tenantId+orderId` 重算权限，不信任模型租户字段。
- **四层校验**：`validateProposal`(结构) → `refundPolicy.check`(语义) → `authorizationService`(资源) → 风险策略；`IdempotencyKey` 服务端生成绑定 `commandHash`，审批 Token 绑定参数（参数变则重批）。
- **状态机**：`PENDING→EXECUTING→SUCCEEDED/FAILED/UNKNOWN`，超时进 `UNKNOWN` 对账不重放。
- **审计**：`ToolAuditEvent` 记录请求/租户/用户/工具/参数Hash/风险级/决策/幂等键/状态，PII 不全文入库、加密受控存储。
- **Spring AI 安全层**：仅传当前身份允许的 `ToolCallback`；自定义 `ToolCallbackResolver` 拒未授权名；`ToolCallingManager` 归一化+鉴权+幂等；`ToolCallingAdvisor` 控预算/阻断。
- **数据隔离**：RAG 检索 / Memory namespace / 缓存键 / Trace 索引均带租户及权限边界；检索前按 `tenant_id`+ACL 过滤；多租户存储/索引/缓存键隔离；网络出口白名单拒私网/元数据。

### 5.3 大模型网关（统一治理入口）
> 来源：`素材收集/05-javaguide-ai.md` ⑤

- **定位**：API 网关能力 + 模型调用控制面，位于应用层与模型供应商之间的统一治理入口（未必独立服务，可应用内轻量模块）。**Router 只选模型；Gateway 管整次调用全生命周期**。
- **解决直连痛点**：模型名写死→注册表配置化；Key 分散→统一密钥；供应商限流→限流/Fallback/熔断；成本不可见→usage+归因；日志缺失→Trace+Prompt 版本；SDK 分散→Provider Adapter 统一封装。
- **核心能力**：多模型统一接入（OpenAI 兼容入口 + Provider Adapter 转各家协议）；模型路由（按 scene/Token/套餐/风险/模型状态，绑定 tier 而非具体模型名）；限流配额（用户/租户/模型/供应商/Token 五维，estimate→reserve→usage→reconcile 预算）；观测审计（request_id+route_reason+usage 脱敏留存）。
- **自研组件**：API Adapter / Auth-Tenant / Prompt Renderer / Token Budget Estimator / Model Registry / Router / Provider Adapter / Retry-Fallback / RateLimiter / Cost Tracker / Observability / Audit Log。第一版先统一 API+Adapter+日志，再补路由/Fallback/预算。
- **选型**：起步轻量自研；多供应商快速接入看 LiteLLM；已有 Kong 看 Kong AI Gateway；已在 Cloudflare 看 Cloudflare AI Gateway。顺序：**先工程治理，再智能路由**。

### 5.4 安全设计原则
1. 模型输出不可信（视为待校验操作建议）；2. 后端兜底限制损害（鉴权/最小权限/审批/隔离阻止未授权）；3. 全面不可信输入（用户/网页/RAG/Memory/MCP/模型/Skill）；4. 最小权限精细拆分；5. 分层防御（Prompt 降概率 + 后端强控制 + 隔离 + 审计）；6. 安全 Badcase 随模型/Prompt/Schema/MCP/Skill/权限版本化回归。
