# 平台建设（横向支撑域）

> 分级：🔴 待验证方案（内容随纵向阶段深化回灌）｜ 来源规划：jeecg.com / doc.ruoyiai.chat / ai-agent-book 部署与平台章节

## 核心能力域

1. **模型管理平台**：模型注册、版本、档位路由、A/B 灰度（参考 Ragent `infra-ai` 档位/首包探测/熔断）。
2. **Prompt 管理平台**：版本化、灰度、效果回归（对齐评估体系 `../01-通用理论原理层/1.6-评估体系.md`）。
3. **Agent 编排平台**：可视化编排、多 Agent 协作（参考 Nexus 三层执行器 / Graph Engineering `../01-通用理论原理层/1.5-多Agent协作与编排.md`）。
4. **数据服务平台**：知识库管理、入库 Pipeline、文档结构图谱（参考 Ragent 入库 / Nexus Neo4j 结构图谱）。

## 二、开源/商业 LLMOps 平台能力对照（R3 Dify + R2 AutoGPT 参照）

> 来源：`github.com/langgenius/dify`（低代码 Agent 构建平台）、`github.com/Significant-Gravitas/AutoGPT`（自主 Agent 平台）。补足"低代码 Agent 搭建平台"与"自主 Agent 运行时"两类能力视角（G2 / 部分 G1）。

### 2.1 平台能力矩阵

| 平台 | 形态 | 核心能力 | 部署方式 | 与本库 Java 栈关系 |
|------|------|----------|----------|-------------------|
| **Dify**（langgenius） | 低代码 Agent 构建平台 | 可视化 Workflow 画布、RAG Pipeline（PDF/PPT 解析）、Agent（沙箱内执行命令/装包/读写文件）、Prompt IDE、LLMOps（日志/性能分析）、BaaS API；观测集成 Opik/Langfuse/Phoenix | Docker Compose 自托管（CPU≥2/RAM≥4GiB）/ 云 / 企业版 | 与 RuoYi AI/JEECG AI **同类但多"低代码画布 + 生态市场"**；偏快速搭建而非深度企业集成 |
| **AutoGPT**（Significant-Gravitas） | 自主 Agent 平台 | AutoPilot（自然语言→agent）、Build（可视化画布）、Marketplace（社区 agent）、Agents（运行/成本看板）；目标驱动、定时/触发运行；连接 45+ 平台（Gmail/Slack/GitHub/Jira/Salesforce…） | 托管平台（付费）/ 自托管（免费、自带密钥） | 定位"**自主执行运行时**"，与 Workflow 人工编排画布互补（见 1.1 第五范式） |
| **RuoYi AI / JEECG AI** | Java 企业级平台 | 企业级助手 / 低代码+AIGC；强权限·事务·企业集成 | 自托管（Java 微服务） | 强在"嵌入企业 Java 体系"，弱在低代码画布与自主运行时 |

### 2.2 选型框架（呼应战略洞察"混合落地"）
- 要**低代码快速搭 Agent/Workflow + 社区生态** → Dify；
- 要**目标驱动、少人工编排的自主执行** → AutoGPT；
- 要**深度嵌入企业 Java 微服务、权限/事务/治理一体化** → 自研（Ragent/Nexus）或 RuoYi AI / JEECG AI；
- **混合策略**：Dify / AutoGPT 做原型与轻量场景，核心生产链路用 Java 栈自研（对齐战略洞察"用 Java/Go 做核心编排，Python 做模型调用"）。

### 2.3 对平台化能力域的反哺
- 把 Dify 的"可视化 Workflow + 生态市场"、AutoGPT 的"自主运行时 + 成本看板"作为平台能力域（模型管理/Prompt 管理/Agent 编排/数据服务）的**外部对照基线**，回灌 ① 的四大能力域设计。
